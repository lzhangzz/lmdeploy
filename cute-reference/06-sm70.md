# SM70 (Volta) Specifics

SM70 introduced tensor core MMA via quadpair (8-thread) HMMA instructions.
All MMA operates at 8×8×4 granularity with FP16 or FP32 accumulation.

## MMA Atoms

SM70 MMA operates at the **quadpair** level — 8 threads collaborate on each 8×8×4 multiply.
A full warp (32 threads) runs 4 quadpairs in parallel for a 16×16×4 operation.

### Operation Structs

| Atom | Types (D, A, B, C) | Transpose | Shape |
|------|---------------------|-----------|-------|
| `SM70_8x8x4_F16F16F16F16_TN` | f16, f16, f16, f16 | TN | 8×8×4 |
| `SM70_8x8x4_F16F16F16F16_NT` | f16, f16, f16, f16 | NT | 8×8×4 |
| `SM70_8x8x4_F16F16F16F16_NN` | f16, f16, f16, f16 | NN | 8×8×4 |
| `SM70_8x8x4_F16F16F16F16_TT` | f16, f16, f16, f16 | TT | 8×8×4 |
| `SM70_8x8x4_F32F16F16F32_TN` | f32, f16, f16, f32 | TN | 8×8×4 |
| `SM70_8x8x4_F32F16F16F32_NT` | f32, f16, f16, f32 | NT | 8×8×4 |
| `SM70_8x8x4_F32F16F16F32_NN` | f32, f16, f16, f32 | NN | 8×8×4 |
| `SM70_8x8x4_F32F16F16F32_TT` | f32, f16, f16, f32 | TT | 8×8×4 |

### Thread ID

Quadpair threads map to warp thread indices:
```cpp
using ThrID = Layout<Shape <_4, _2>,
                     Stride<_1,_16>>;
// Maps logical thread [0,8) → warp index [0,4) ∪ [16,20)
```

### Accumulator Layout (CLayout)

Each quadpair thread owns 8 accumulator values. The CLayout maps `(thread_id, value_id)` to `(m, n)`:
```cpp
// (T8,V8) -> (m,n)  for FP32 accumulation
using CLayout = Layout<Shape <Shape <_2, _2,_2>, Shape <_2,_2, _2>>,
                       Stride<Stride<_1,_16,_4>, Stride<_8,_2,_32>>>;
```

### A/B Layouts

Depend on transpose mode:
```cpp
// TN: A is M-major, B is K-major (for ALayout/BLayout written as (m,k)/(n,k))
using ALayout = Layout<Shape <_8,_4>, Stride<_1,_8>>;  // (T8,V4) -> (m,k)
using BLayout = Layout<Shape <_8,_4>, Stride<_1,_8>>;  // (T8,V4) -> (n,k)

// NT: more complex interleaving
using ALayout = Layout<Shape <Shape <_4,_2>,_4>, Stride<Stride<_8,_4>,_1>>;
```

## TiledMMA Construction

SM70's natural tiling unit is 16×16×4 (4 quadpairs × 8×8×4 each):

```cpp
// 16×16×4 WMMA-like: tile 2×2 quadpairs
TiledMMA mma = make_tiled_mma(SM70_8x8x4_F32F16F16F32_NT{},
                              Layout<Shape<_2,_2>, Stride<_2,_1>>{});

// 32×32×4: tile across threads AND values
TiledMMA mma = make_tiled_mma(SM70_8x8x4_F32F16F16F32_NT{},
                              Layout<Shape<_2,_2>, Stride<_2,_1>>{},
                              Tile<_32,_32,_4>{});

// With M-mode permutation for contiguous smem access
TiledMMA mma = make_tiled_mma(SM70_8x8x4_F32F16F16F32_NT{},
                              Layout<Shape<_2,_2>, Stride<_2,_1>>{},
                              Tile<Layout<Shape<_4,_4,_2>, Stride<_1,_8,_4>>,
                                   _32, _4>{});
```

## Copy

SM70 has no dedicated copy atoms — it uses standard `ld.global` / `st.shared` instructions.
The `copy` algorithm dispatches to sequential loads.

## Key Difference from Later Architectures

- SM70: quadpair (8 threads) per MMA, FP16 only, no async copy
- SM75: warp (32 threads) per MMA, adds INT8, adds cp.async + LDSM
- SM80: warp-level, adds TF32/BF16/FP64, enhanced cp.async
