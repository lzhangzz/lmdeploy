# SM75 (Turing) Specifics

SM75 introduced warp-level MMA (16×8×8) and `cp.async` / `ldsm` copy instructions.

## MMA Atoms

SM75 MMA operates at the **warp** level (32 threads), with larger shapes than SM70's quadpair.

| Atom | Types (D, A, B, C) | Shape |
|------|---------------------|-------|
| `SM75_16x8x8_F32F16F16F32_TN` | f32, f16, f16, f32 | 16×8×8 |
| `SM75_8x8x16_S32S8S8S32_TN` | s32, s8, s8, s32 | 8×8×16 |

## Copy Atoms

SM75 introduced `ldsm` (load shared memory) instructions that load from shared memory
to registers with automatic transposition.

### Normal (non-transposing) loads

| Atom | Description |
|------|-------------|
| `SM75_U32x1_LDSM_N` | 1×32-bit load, normal layout |
| `SM75_U32x2_LDSM_N` | 2×32-bit load, normal layout |
| `SM75_U32x4_LDSM_N` | 4×32-bit load, normal layout |

### Transposing loads

| Atom | Description |
|------|-------------|
| `SM75_U16x2_LDSM_T` | 2×16-bit load, transposed |
| `SM75_U16x4_LDSM_T` | 4×16-bit load, transposed |
| `SM75_U16x8_LDSM_T` | 8×16-bit load, transposed |

Transposing loads are critical for MMA: the A matrix may be stored column-major in smem
but the MMA instruction expects it row-major. `LDSM_T` handles this at the hardware level.

## Copy Pattern

```cpp
// gmem → smem: use cp.async (SM80 atoms, but works on SM75+)
TiledCopy copy_a = make_tiled_copy_A(SM80_CP_ASYNC_CACHEALWAYS<16>{}, ...);

// smem → registers: use ldsm
TiledCopy s2r_copy = make_tiled_copy_A(SM75_U32x4_LDSM_N{}, mma_layout, tiler);
ThrCopy thr_s2r = s2r_copy.get_slice(threadIdx.x);
Tensor tXsA = thr_s2r.partition_S(sA);    // smem source
Tensor tXrA = thr_s2r.retile_D(tCrA);     // register destination
copy(s2r_copy, tXsA(_,_,k_block), tXrA(_,_,k_block));
```

## Key Difference from SM70

- SM70: quadpair (8 threads), no cp.async, no ldsm, FP16 only
- SM75: warp (32 threads), adds cp.async + ldsm, adds INT8 MMA
