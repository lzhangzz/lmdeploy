# 09: DeltaNet register pass writes conv bytes before tp_size is validated

> *This was generated by AI during triage.*

**What:** `DeltaNet`'s register pass sizes the conv-state registration with
the module config's `tp_size`, while all recurrent-state math uses the
engine's attn_tp × attn_cp product. Equality of the two is enforced only
later, at bind (`RegisterLayer`). A mismatched module would write wrong byte
counts into the checkpoint category and only then abort — fail-loud, but
after the registry has been dirtied. The retired executor computed
everything from the engine's tp directly.

**Direction:** validate the module `tp_size` against the engine's
attn_tp × attn_cp during the register pass, before any bytes are written.
The engine tp must reach the module through the registry: the register pass
installs no ambient engine-param guard (verified: the pybind `register_cache`
exposure is a bare call, and the Python driver invokes it outside any weight
context), so extend the registry's engine-derived surface the way `set_layout`
already carries engine values, rather than relying on the ambient guard the
MoE factory uses at create time.

**Category:** bug (latent)
**Status:** wontfix
