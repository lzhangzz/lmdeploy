# 07: Wave-guarded batch-slot refill assumes the engine's op cadence

> *This was generated by AI during triage.*

**What:** `Attention` and `DeltaNet` refill their batch-level setup slots
only when the setup wave has advanced since the last fill (the wave-stamp
guard that makes per-layer Run dispatch safe). `kForward` does not advance
the wave. The engine's cadence (add → setup → prepare → forward per step)
always separates same-phase setups with a non-setup op, so the guard is
correct today — but nothing records that assumption. A future caller issuing
two same-phase setups with no intervening op would silently reuse stale
batch slots.

**Direction:** record the cadence contract where the wave guard is defined
(the engine README's contracts section): same-phase `kSetup` repeats are
only safe with an intervening non-setup op. Alternatively make the refill
unconditional, if profiling shows the refill is cheap enough not to matter.

**Category:** enhancement
**Status:** needs-triage
