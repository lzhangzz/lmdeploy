# 01: Vision Attention modules share the text AttentionState through the bind walk

> *This was generated by AI during triage.*

**What:** the bind walk reaches the vision tree (`VisionModelWeight` stops
only `register_cache`, not `bind`), and both internvit and qwenvit
instantiate `Attention` modules. `Attention::bind` rendezvouses every
`Attention` in the tree — text and vision — on one per-rank `AttentionState`
via the shared-state map, so vision-side Attention binds against the text
model's attention state. The state is created by whichever `Attention` the
walk visits first and is sized from that module (rope config, workspace
buffers); today the text tower is visited first, so the exemplar is text
layer 0. Vision forwards never touch the state, so this is benign today, but
the coupling is walk-order dependent and accidental rather than designed.

**Direction:** pick one deliberately: (a) give vision-side Attention a
state-free bind path, (b) keep the sharing and document it as a contract
(text-first walk order, vision never uses the state), or (c) scope the shared
state per model tower. This is a design call, not a mechanical fix.

**Category:** enhancement
**Status:** ready-for-human
