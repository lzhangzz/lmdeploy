# 05: Standalone linear.py Weights can dangle after their Linear is collected

> *This was generated by AI during triage.*

**What:** in the standalone `linear.py` flow, a `Weight` wraps a bound C++
`Linear` module (`Weight._impl`). Binding captures a raw pointer to the
per-rank GEMM engine owned by the `Linear`'s Context (`Linear._engine`), but
the `Weight` holds no reference to that owner: the module's `bind` pybind
exposure has no keep-alive policy, and the per-device `Linear` cache is a
weak-value map. If the owning `Linear` is garbage-collected or closed while
`Weight`s built from it survive, their next forward / `get_exec_plan` /
`tune` dereferences freed memory. The never-bound `TM_CHECK` in `engine()`
only catches unbound modules, not dangling ones. The retired design passed
the executor explicitly per call with pure-data weights, so the hazard is
new with executable modules. The documented flow (keep the `Linear` alive
for as long as its weights are used) never triggers it.

**Direction:** make `Weight` co-own what it needs: either a keep-alive
policy on the module `bind` call, or store the bound engine owner on the
`Weight` — and have `Linear.close()` leave surviving weights in a safe,
loudly-failing state rather than dangling.

**Category:** bug (latent)
**Status:** needs-triage

## Comments

> *This was generated by AI during triage.*

2026-09-20: triage verified the mechanism: the standalone `Module.bind`
pybind shim binds modules to the caller-owned Context, `Weight` holds only
the module, and the Context's sole Python owner is `Linear._engine` — so
`py::keep_alive<1, 2>` on the bind def (nurse = module, patient = Context)
makes bound modules pin the engine; surviving Weights keep working instead
of dangling after the Linear dies. `Linear.close()` must document that bound
weights pin the engine. Kept needs-triage per maintainer.

2026-09-20: under discussion — the maintainer questions whether the
current linear.py surface (Weight handle + Linear-executes-Weight) is right
at all; see issue 10. Nothing decided. The keep-alive fix analyzed above
stands as the narrow fix if the surface survives the discussion unchanged;
this ticket stays open regardless of issue 10's outcome.

2026-09-20 (later): issue 10's direction is maintainer-approved — one
per-weight Linear that holds its weight and pins its device engine. The
dangle this ticket describes cannot arise in that shape: resolved by
