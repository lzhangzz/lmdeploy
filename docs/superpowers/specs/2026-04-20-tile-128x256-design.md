# Tile Size 128x256 for Sample 09

## Overview

Change the CTA tile size in sample 09 from 128x128x64 to 128x256x64. Increases N dimension to improve arithmetic intensity — each TMA load of A is reused across 256 columns of B instead of 128, doubling compute per byte loaded from gmem.

Modifies: `cute-reference/samples/09_bf16_gemm_sm90_pipe_tma_ws_persistent.cu`

## Problem

The 128x128 tile underutilizes the A operand: each A tile (128x64 bf16) is loaded once but only contributes to 128 output columns. Doubling N to 256 doubles the reuse factor, increasing arithmetic intensity and throughput.

## Solution

Swap the WGMMA atom from 64x128 to 64x256. The atom's N dimension doubles, which doubles the CTA tile's N dimension. All other architecture (warp specialization, pipeline, epilogue) is unchanged.

## Key Changes

### 1. Atom and Tile Size

```
Old: SM90_64x128x16_F32BF16BF16_SS<K,K>, bN=128, CTA tile 128x128x64
New: SM90_64x256x16_F32BF16BF16_SS<K,K>, bN=256, CTA tile 128x256x64
```

The WGMMA atom is 64x256x16 (128 threads = 1 warpgroup). TiledMMA `Layout<Shape<_2,_1>>` tiles M by 2, giving 256 consumer threads = 2 warpgroups covering the 128x256 CTA tile.

### 2. Host Function (4 lines)

- `bN = Int<128>` → `bN = Int<256>`
- `SM90_64x128x16_F32BF16BF16_SS` → `SM90_64x256x16_F32BF16BF16_SS`
- Assertion: `n % 128 == 0` → `n % 256 == 0`
- Banner: update tile size description

### 3. Smem Budget

| Component | Elements | Bytes |
|-----------|----------|-------|
| A (128x64x3, GMMA swizzled) | 24,576 bf16 | 49,152 |
| B (256x64x3, GMMA swizzled) | 49,152 bf16 | 98,304 |
| C (128x256, plain col-major) | 32,768 bf16 | 65,536 |
| Pipeline barriers | — | 48 |
| **Total** | | **~213 KB** |
| SM90 max per SM | | **228 KB** |
| Headroom | | **~15 KB** |

Note: Pipeline barriers use `typename cutlass::PipelineTmaAsync<3>::SharedStorage` which is small (mbarrier objects + aligned padding). The 48-byte estimate above is approximate; actual barrier storage may be slightly different but does not materially affect the headroom calculation.

### 4. Register Pressure

CLayout_64x256 gives 128 F32 accumulators per thread (vs 64 for 128x128). With other registers, expect ~200 total. Monitor for spills.

## What Stays the Same

- **bM, bK, bP:** Int<128>, Int<64>, Int<3> — unchanged
- **TiledMMA tiling:** `Layout<Shape<_2,_1>>` — unchanged
- **Kernel code:** No changes — same pipeline, same warpgroup sync, same epilogue
- **Thread count:** 384 (256 consumer + 128 producer)
- **Pipeline:** PipelineTmaAsync with 3 stages
- **Epilogue:** STSM + TMA store
- **Kernel launch:** 384 threads, `__launch_bounds__(384, 1)`
