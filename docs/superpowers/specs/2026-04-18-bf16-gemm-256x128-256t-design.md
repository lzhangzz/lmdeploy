# BF16 GEMM SM80 Pipe — (256, 128, 64) Tile with 256 Threads

## Overview

Modify the existing `bf16_gemm_sm80_pipe.cu` to use a (256, 128, 64) CTA tile with 256
threads (8 warps). The baseline (128, 128, 64) with 128 threads showed ~360 TFLOP/s at
4096^3. The (256, 128, 64) tile with 128 threads catastrophically regressed to ~4.6 TFLOP/s
due to register spilling (each thread holding 256 f32 accumulators instead of 128). Doubling
the thread count restores per-thread register pressure to 128 f32, matching the baseline.

## Parameters

| Parameter | Baseline | New |
|-----------|----------|-----|
| CTA tile (M, N, K) | (128, 128, 64) | (256, 128, 64) |
| MMA atom layout | `Layout<Shape<_2, _2>>` (4 warps) | `Layout<Shape<_4, _2>>` (8 warps) |
| Thread count | 128 | 256 |
| G2S thread layout | `Layout<Shape<_16, _8>, Stride<_8, _1>>` | `Layout<Shape<_32, _8>, Stride<_8, _1>>` |
| Smem sA | (128, 64, 3) swizzled ≈ 48 KB | (256, 64, 3) swizzled ≈ 96 KB |
| Smem sB | (128, 64, 3) swizzled ≈ 48 KB | unchanged ≈ 48 KB |
| Total smem | ~96 KB | ~144 KB |
| Per-thread accumulators | 128 f32 | 128 f32 (unchanged) |

## What Changes

Three mechanical substitutions in `bf16_gemm_sm80_pipe.cu`:

1. **CTA tile sizes** (host function): `bM = Int<128>` → `Int<256>`, `cta_tiler = make_shape(bM, bN, bK)` comment update

2. **MMA atom layout** (host function): `Layout<Shape<_2, _2>>` → `Layout<Shape<_4, _2>>`, static_assert updates to expect 256 threads

3. **G2S TiledCopy thread layout** (host function, both A and B):
   `Layout<Shape<_16, _8>, Stride<_8, _1>>` → `Layout<Shape<_32, _8>, Stride<_8, _1>>`
   32 threads in M/N dimension, 8 in K = 256 threads total

4. **Benchmark assert**: `m % 128 == 0` → `m % 256 == 0`

## What Stays the Same

- MMA atom: `SM80_16x8x16_F32BF16BF16F32_TN`
- Tile override: `Tile<_32, _32, _16>`
- Pipeline depth: 3 stages (`bP = Int<3>`)
- Swizzle pattern: `Swizzle<3, 3, 3>` with `Layout<Shape<_8, Shape<_8, _8>>, Stride<_8, Stride<_1, _64>>>` — valid for (256, 64) since 256/8=32 divides evenly
- bK = 64, bN = 128
- G2S copy atom: `SM80_CP_ASYNC_CACHEALWAYS<uint128_t>`
- S2R atoms: `SM75_U32x4_LDSM_N` (auto-tiled by `make_tiled_copy_A/B`)
- Pipeline logic, main loop, prefetch, drain, epilogue — all unchanged
- Kernel device code — completely unchanged (all changes are in host function parameters)

## Register Pressure Analysis

Per-thread accumulator count = (BLK_M × BLK_N) / num_threads:
- Baseline: (128 × 128) / 128 = 128 f32 per thread
- Failed (256×128 / 128 threads): 256 f32 → register spilling, ~80x slowdown
- This design (256×128 / 256 threads): 128 f32 → same as baseline

## Occupancy

L20Y has 192 KB shared memory per SM, 2048 max threads per SM.

- Baseline: ~96 KB smem → 2 blocks/SM × 128 threads = 256 threads/SM
- This design: ~144 KB smem → 1 block/SM × 256 threads = 256 threads/SM

Same thread occupancy. The larger tile trades inter-CTA parallelism for intra-CTA data reuse
in the M dimension (each CTA processes 2× more M output elements, reducing grid dimensions).
